# Архитектура FileScope

## Цель

Архитектура первой версии отделяет пользовательский интерфейс от будущих механизмов анализа. Демонстрационные данные не должны становиться прямой зависимостью страниц и заменяются через сервисные контракты.

## Слои

1. **Presentation** — React-компоненты, страницы, виджеты, маршрутизация и доступность.
2. **Application** — пользовательские сценарии: выбор объекта, запрос проверки, изменение настроек, mock-действия.
3. **Domain** — модели объектов, результатов, индикаторов, лицензии и карантина.
4. **Infrastructure** — локальные настройки, mock-сервисы, будущие адаптеры баз и обновлений.
5. **Native bridge** — минимальный слой Tauri для окна, трея, файловых диалогов и системных событий.

## Правила зависимостей

- UI обращается к сервисным интерфейсам, а не к конкретным анализаторам.
- React-компоненты не выполняют нативные команды напрямую; используется `shared/native`.
- Пароли архивов и выбранные пользователем объекты не сохраняются между сессиями.
- Настройки хранятся через `ISettingsService`.
- Реальные пользовательские объекты не получают демонстрационный вердикт.
- Сетевой доступ в версии 0.1.0 отсутствует.

## Подготовленные точки расширения

- `IFileAnalysisService`;
- `IUrlAnalysisService`;
- будущие `IArchiveAnalysisService`, `IInstalledProgramsService`;
- `ISettingsService`;
- будущие `IUpdateService`, `ILicenseService`, `IQuarantineService`;
- Tauri events для навигации из системного трея.

## Ограничение версии 0.1.0

Версия 0.1.0 является завершённой UI-версией без аналитического ядра. Все результаты, индикаторы, программы и элементы карантина являются безопасными mock-данными с явной маркировкой.
