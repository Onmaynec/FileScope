# FileScope v0.3.4 — release blockers перед ручным QA

Документ фиксирует hardening-проверки, найденные после первого зелёного CI PR #78.

## Storage/privacy

- полное удаление истории должно удалять current, legacy и migration-backup report payload;
- ошибки `getItem`/`removeItem` не должны интерпретироваться как пустое/успешно очищенное хранилище;
- `storageVersion=current` вместе с `reportSchemaVersion>current` открывается только read-only и никогда не перезаписывается;
- raw report с future `schemaVersion` не должен теряться из-за автоматической миграции.

## Backend boundaries

- AnalysisLimits валидируются и ограничиваются в Rust после IPC, frontend sanitization не считается security boundary;
- чистая остановка по resource limit не повышает threat score;
- ZIP не содержит non-finite float в сериализуемом report contract;
- ZIP использует устойчивую политику открытия объекта и проверку неизменности открытого handle.

## Проверки

Каждый пункт должен иметь regression-тест и пройти полный frontend/Rust/Tauri/Windows CI. После этого PR #78 остаётся Draft только до ручного checklist `docs/product/v0.3.4-manual-qa.md`.
