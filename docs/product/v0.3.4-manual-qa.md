# FileScope v0.3.4 — ручная проверка перед merge

Этот checklist выполняется владельцем после полного зелёного CI на финальном HEAD `chore/v0.3.4-readiness`.

## Обновление и история

- обновить установленную/portable v0.3.3 до сборки v0.3.4;
- убедиться, что legacy history читается после первого запуска;
- перезапустить приложение и убедиться, что мигрированная история сохраняется;
- проверить corrupted, oversized и future history: приложение запускается, показывает защитный статус и не перезаписывает исходные данные;
- нажать «Удалить все отчёты», перезапустить приложение и убедиться, что current, legacy и migration-backup payload не восстановились;
- проверить отказ storage removal: UI не должен сообщать об успешном удалении.

## Файлы и лимиты

- проверить небольшой безопасный PE и обычный файл;
- проверить файл больше `maximumFileSizeBytes`: результат должен быть `stoppedByLimit`, а не `highRisk` только из-за лимита;
- проверить прямой IPC/DevTools вызов с экстремальными AnalysisLimits: Rust должен применить безопасные пределы;
- изменить файл во время анализа и убедиться, что возвращается `fileChanged`.

## ZIP

- проверить обычный ZIP без извлечения содержимого;
- проверить ZIP с `../`, абсолютным/drive-like путём и двойным расширением;
- проверить ZIP с количеством записей выше лимита: неполнота отображается отдельно от threat score;
- проверить ZIP с compressed=0/uncompressed>0: JSON/HTML не содержат `Infinity`/`NaN`, UI показывает бесконечный коэффициент однозначно;
- проверить symlink/junction/reparse/UNC сценарии на Windows: объект не должен быть проанализирован через подменённый путь.

## URL

- пассивная проверка не выполняет сеть;
- credentials не попадают в report/history/export;
- активная проверка блокирует localhost/private/metadata ranges и повторно проверяет redirect;
- extreme timeout/redirect limits из renderer ограничиваются Rust backend.

## Очередь и UI

- 150+ synthetic items: прокрутка, поиск и фильтры;
- дубликаты не должны оставлять `selectedId`, которого нет в очереди;
- ручной выбор старого отчёта не должен сбрасываться при старте следующего задания;
- проверить светлую/тёмную тему и узкое окно;
- проверить очистку истории, Escape и безопасный initial focus.

## Сборки

- portable EXE запускается без отдельной консоли;
- NSIS устанавливается/удаляется корректно;
- ярлык, окно, taskbar и tray используют один логотип;
- version UI = 0.3.4;
- JSON/HTML export открываются и содержат согласованные schema/app/analyzer/rule versions.

## Условие GO

Ручная проверка считается пройденной только если нет потери/скрытого сохранения истории, ложного успешного удаления, обхода backend resource budgets, неверного threat verdict из-за одних лимитов и рассинхронизации JSON contract.
