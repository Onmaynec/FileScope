# FileScope v0.4.0 — ручной Windows QA

Запускать этот checklist только на Windows x64 artifact, собранном из финального HEAD `feature/v0.4.0`, после полностью зелёных Policy Pack, основного CI и Security fuzz smoke.

## 1. Чистая установка и базовый запуск

- [ ] Установить NSIS build v0.4.0 на чистый профиль Windows.
- [ ] Проверить версию `0.4.0` в UI/metadata.
- [ ] Запустить portable EXE отдельно от установленной версии.
- [ ] Проверить старт, закрытие в tray, Quit, повторное открытие окна и основные страницы.

## 2. Новый Rust/Tauri history store

- [ ] На пустом профиле открыть Settings → «История и приватность»; backend должен отображаться как Rust/Tauri, store — пустой.
- [ ] Выполнить анализ файла и URL, перезапустить FileScope и подтвердить сохранение history.
- [ ] Удалить один report, перезапустить и подтвердить, что он не восстановился.
- [ ] Выполнить «Удалить всю историю», перезапустить и подтвердить пустой store.
- [ ] Убедиться, что Settings/analysis limits после удаления report history не сбросились.

## 3. DPAPI current-user protection

- [ ] После сохранения report UI показывает `DPAPI / Current user`, а не неподтверждённую/legacy защиту.
- [ ] Найти app-data history directory и убедиться, что новые generations имеют бинарный `.bin` формат.
- [ ] Открыть `.bin` в hex/text viewer: target URL, file path, report id и другие контрольные plaintext строки не должны читаться как обычный JSON.
- [ ] Перезапустить FileScope под тем же Windows user: history должна успешно расшифроваться и открыться.
- [ ] Скопировать encrypted generation в другой тестовый Windows user/profile: FileScope не должен расшифровать её как валидную историю и не должен автоматически заменить её пустым store.
- [ ] При невозможности decrypt UI должен показывать protective/corrupted state, а не утверждать «история пуста».

## 4. Миграция v0.3.x WebView history

- [ ] Создать/сохранить несколько реальных reports в проверенной v0.3.x/v0.3.4 сборке.
- [ ] Обновиться до v0.4.0 без предварительной очистки данных.
- [ ] При первом открытии history reports должны появиться в v0.4.0.
- [ ] Проверить, что в Rust store записана privacy-minimized копия, а legacy source не получает новые report writes.
- [ ] Создать новый report в v0.4.0, перезапустить и подтвердить, что authoritative копия — Rust/Tauri store.
- [ ] Проверить rollback source согласно migration policy и отсутствие double-write новых reports в legacy localStorage.

## 5. Миграция раннего plaintext history v2 → DPAPI

- [ ] Подготовить валидную plaintext `reports-v2-*.json` generation раннего development build.
- [ ] Запустить v0.4.0: history должна прочитаться.
- [ ] После policy enforcement должна появиться новая DPAPI `.bin` generation.
- [ ] Валидная plaintext generation должна удалиться только после успешной encrypted publication.
- [ ] Future/corrupted plaintext generation не должна автоматически удаляться DPAPI cleanup.

## 6. Privacy policy

- [ ] По умолчанию file report history не содержит полный путь — только имя файла.
- [ ] По умолчанию URL history не содержит credentials, query и fragment.
- [ ] `Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key`, `X-Auth-Token` и аналогичные sensitive headers не должны сохраняться в history.
- [ ] Включить «Хранить полный путь», сохранить новый file report и подтвердить ожидаемое поведение.
- [ ] Включить «Хранить полный URL», сохранить URL с query/fragment: query/fragment сохраняются, но credentials всё равно удаляются.
- [ ] Вернуть строгую privacy policy и подтвердить, что ранее сохранённая history переписана в минимизированный вид.

## 7. Retention

- [ ] `Только текущий сеанс`: новый report виден до закрытия приложения и исчезает после полного restart; существующая persistent history не удаляется только из-за выбора session-mode.
- [ ] Отключить «Сохранять новые отчёты»: новый report остаётся только в текущем session, ранее сохранённая history сохраняется.
- [ ] `1 день`: reports старше cutoff физически исчезают из authoritative store после policy enforcement.
- [ ] Повторить для `7 дней` и `30 дней` на тестовых датах/fixtures.
- [ ] `Без автоудаления`: валидные старые reports не удаляются retention policy.

## 8. Crash/recovery

- [ ] Иметь минимум одну валидную generation.
- [ ] Во время следующего history write принудительно завершить процесс FileScope/Windows session.
- [ ] После restart приложение должно либо открыть новую полностью опубликованную generation, либо восстановить предыдущую валидную; частичный temp-файл не должен становиться authoritative.
- [ ] Повредить newest generation вручную и подтвердить recovery предыдущей валидной generation.
- [ ] Если валидной предыдущей копии нет, UI должен показать corrupted/unavailable state без автоматического overwrite.

## 9. Read-only / storage failure

- [ ] Сделать history directory недоступным для записи или заблокировать generation другим процессом.
- [ ] Новый анализ не должен завершаться ложным `persisted=true`.
- [ ] UI должен сообщить, что report доступен только в session, если persistence не подтверждена.
- [ ] После восстановления доступа повторный анализ должен сохраняться нормально.
- [ ] Полная очистка при blocked file не должна показывать ложный success.

## 10. Portable policy

- [ ] Запустить portable EXE: persistent history должна использовать per-user app-data, а не каталог рядом с EXE.
- [ ] Переместить portable EXE в другой каталог — history того же Windows user остаётся доступной через app-data.
- [ ] Скопировать только portable EXE на другой Windows PC/user — локальная history исходного компьютера не должна переноситься вместе с ним.
- [ ] Скопировать DPAPI generation на другой PC/user — она не должна становиться читаемой.
- [ ] Явный JSON/HTML export report остаётся читаемым как пользовательский export и не считается частью encrypted history store.

## 11. UI состояния

- [ ] Settings показывает backend, размер persistent history и количество reports.
- [ ] Protection badge корректно различает empty / DPAPI / plaintext migration / mixed / unavailable.
- [ ] После clear размер становится 0 и protection state — empty/DPAPI при следующей записи.
- [ ] Тёмная/светлая тема, resize, клавиатурная навигация и тексты новых controls визуально корректны.

## 12. Регрессия анализатора

- [ ] File/ZIP/URL passive/URL active работают как в финальной v0.3.4.
- [ ] Queue 150+ items, duplicates, manual selection и cancellation не регрессировали.
- [ ] JSON/HTML export открывается и сохраняет корректные verdict/completeness semantics.
- [ ] Limitation/operational indicators не повышают Risk Score сами по себе.

## GO / NO-GO

**GO** только если одновременно выполнено:

- финальный HEAD прошёл Policy Pack, основной CI, Windows/NSIS и Security fuzz;
- реальная миграция v0.3.x подтверждена с restart;
- DPAPI current-user status подтверждён на реальной Windows machine;
- нет plaintext fallback при ошибке DPAPI;
- crash/recovery и read-only failure не приводят к потере/тихому overwrite данных;
- clear не оставляет известных report payload;
- portable policy соответствует документации;
- #42 и #49 выполнены по их release criteria.

**NO-GO** при любой потере history без явного действия пользователя, ложном `persisted=true`, неожиданном plaintext persistence, чтении encrypted history другим Windows user/machine, автоматическом overwrite future/corrupted store или несоответствии migration policy.
