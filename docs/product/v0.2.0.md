# FileScope v0.2.0

## Статус

Рабочая версия находится в ветке `feature/v0.2.0` и черновом Pull Request #8. До ручной проверки владельцем она не переносится в `develop`, не сливается в `main`, не получает тег и не публикуется как GitHub Release.

## Назначение

Версия 0.2.0 превращает FileScope из кликабельного UI-прототипа в первую функциональную версию с реальным локальным статическим анализом. Проверяемые объекты не запускаются и не отправляются во внешние сервисы.

## Анализ файлов

FileScope выполняет:

- потоковое вычисление SHA-256;
- определение фактического типа по сигнатуре содержимого;
- сравнение расширения с фактическим форматом;
- поиск двойных расширений;
- оценку энтропии первых данных;
- чтение базовых метаданных файла;
- разбор PE-файлов Windows;
- определение архитектуры, точки входа, секций и импортов;
- поиск API повышенного внимания;
- определение наличия каталога Authenticode.

Наличие каталога Authenticode не означает, что цепочка сертификата проверена или подпись является доверенной.

## Анализ URL

Пассивный анализ выполняется без DNS и HTTP:

- нормализация адреса;
- проверка схемы;
- разбор домена, порта, пути и параметров;
- обнаружение IP вместо домена;
- обнаружение IDN/Punycode;
- поиск встроенных учётных данных;
- оценка длины и числа поддоменов;
- поиск вложенных redirect-параметров;
- распознавание сокращателей ссылок;
- поиск адресов прямой загрузки исполняемых файлов.

Активная проверка запускается только вручную после отдельного согласия. Она выполняет DNS-разрешение и минимальный HEAD- либо Range-запрос без исполнения JavaScript и без загрузки страницы целиком.

## Анализ архивов

Структурный анализ поддерживает ZIP:

- чтение дерева без извлечения содержимого на диск;
- количество и размеры записей;
- глубина каталогов;
- коэффициент сжатия;
- поиск path traversal и абсолютных путей;
- поиск исполняемых файлов;
- поиск двойных расширений;
- поиск вложенных архивов;
- ограничения числа записей и распакованного объёма;
- признаки архивной бомбы.

RAR и 7Z определяются по сигнатуре, но их содержимое в 0.2.0 не разбирается.

## Риск и отчёты

Rule Engine формирует один из четырёх уровней:

1. «Признаков угроз не найдено»;
2. «Требует внимания»;
3. «Высокий риск»;
4. «Опасный объект».

Каждый обнаруженный признак содержит:

- идентификатор;
- категорию;
- серьёзность;
- вклад в оценку;
- технические доказательства;
- понятное описание;
- рекомендацию пользователю.

Отчёты сохраняются локально и экспортируются в JSON или автономный HTML.

## Защитные ограничения

- максимальный размер файла;
- максимальное количество записей ZIP;
- максимальный распакованный объём;
- максимальная глубина архива;
- максимальный коэффициент сжатия;
- таймаут активной URL-проверки;
- лимит перенаправлений.

Ограничения можно настраивать в безопасных пределах, но нельзя полностью отключить.

## Не входит в версию

- запуск объектов в Hyper-V Sandbox;
- поведенческий анализ процессов;
- антивирусный движок и сигнатурная база;
- загрузка в VirusTotal или другие облачные сервисы;
- автоматический карантин реальных файлов;
- полноценная верификация цепочки Authenticode;
- структурный разбор RAR и 7Z;
- браузерное расширение;
- платёжная система и серверная синхронизация.

## Критерии готовности

- ESLint проходит без предупреждений;
- TypeScript strict typecheck проходит;
- frontend unit-тесты проходят;
- production frontend собирается;
- Playwright smoke-тесты проходят;
- `cargo fmt --check` проходит;
- Rust unit-тесты проходят;
- `cargo check` проходит;
- Windows x64 приложение и NSIS-установщик собираются;
- артефакты остаются только в CI и не публикуются как релиз;
- PR остаётся черновиком до решения владельца.
