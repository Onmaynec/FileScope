# Отчёт hardening history storage v0.3.4

После первого зелёного CI PR #78 обнаружены и исправляются два дополнительных класса ошибок, которые должны быть закрыты до ручного тестирования:

1. `clear()` не должен сообщать `persisted=true`, если хотя бы один report/history key удалить не удалось; полное удаление включает migration backup payload.
2. Envelope с текущим `storageVersion`, но будущим `reportSchemaVersion` или вложенным future report обязан оставаться read-only и не должен перезаписываться новым отчётом.

Regression coverage включает ошибку `getItem`, отказ `removeItem`, future envelope, скрытый future report и reload-safe clear semantics.
