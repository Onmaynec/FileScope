# FileScope v0.4.0 — план разработки

## База

- рабочая ветка: `feature/v0.4.0`;
- точка ветвления: финальный hardening HEAD v0.3.4 `78ed2d6a5e4dfed31b348d22a8239d7ca45bf7a7`;
- `chore/v0.3.4-readiness` остаётся отдельной веткой для ручного QA и релизной подготовки;
- изменения v0.4.0 не переносятся обратно в v0.3.4 без отдельного решения.

## Главная цель

Перевести историю отчётов из WebView `localStorage` в контролируемое Rust/Tauri-хранилище, включить политику приватности и retention, защитить persistent history системным Windows DPAPI и сохранить безопасную миграцию/rollback.

## Этап 1 — authoritative Rust/Tauri history storage — КОДОВО ЗАВЕРШЁН

- [x] versioned history envelope на стороне Rust;
- [x] app-data storage вместо WebView storage;
- [x] caps на количество reports и размер payload;
- [x] strict storage/report schema validation до rewrite;
- [x] future/corrupted/oversized состояния без автоматического overwrite;
- [x] crash-safe temporary write + `sync_all` + atomic generation publication;
- [x] предыдущая валидная generation для recovery;
- [x] commands load/save/delete/replace/rewrite/clear/inspect;
- [x] Rust regression tests.

Остаётся ручной crash-during-publication test на реальной Windows machine.

## Этап 2 — миграция localStorage → Rust storage — КОДОВО ЗАВЕРШЁН

- [x] Tauri storage всегда проверяется первым;
- [x] WebView storage используется только как read-only migration source;
- [x] privacy minimization применяется до persistence;
- [x] после успешной миграции Rust storage становится authoritative;
- [x] legacy source не получает новые report writes;
- [x] migration failures не считаются empty и не уничтожают source;
- [x] frontend regression tests покрывают migration/no-double-write/future schema.

Остаётся ручная миграция реальной v0.3.x history с restart/rollback и partial-cleanup failure.

## Этап 3 — privacy и retention — ЗАВЕРШЁН

- [x] переключатель сохранения новых reports;
- [x] retention: current session / 1 / 7 / 30 дней / без автоудаления;
- [x] session-only memory behavior без удаления ранее сохранённой history;
- [x] full paths по умолчанию не сохраняются;
- [x] URL credentials удаляются всегда;
- [x] query/fragment сохраняются только по явной policy;
- [x] sensitive headers не попадают в history persistence;
- [x] policy rewrite применяет stricter privacy и retention к существующей history;
- [x] UI показывает backend, размер store, число reports и полную очистку;
- [x] unit/property/Playwright/Rust/Windows/NSIS regression pipeline зелёный.

## Этап 4 — Windows protection и portable mode — КОДОВО ЗАВЕРШЁН

- [x] системный current-user DPAPI через `CryptProtectData`/`CryptUnprotectData`;
- [x] без собственной криптографии и без файлов ключей;
- [x] `CRYPTPROTECT_UI_FORBIDDEN`, без `CRYPTPROTECT_LOCAL_MACHINE`;
- [x] отсутствие plaintext fallback при DPAPI encrypt failure;
- [x] binary `FSDPAPI1` wrapper и `.bin` generations;
- [x] legacy plaintext v2 migration в DPAPI;
- [x] валидный plaintext source удаляется только после успешной encrypted publication;
- [x] future/corrupted source не удаляется protection cleanup;
- [x] diagnostic protection status в Rust/Tauri/UI;
- [x] portable policy: EXE переносим, persistent history остаётся per-user app-data + DPAPI user-bound;
- [x] реальный Windows CI DPAPI round-trip и plaintext-absence regression test.

Остаётся ручной cross-user/cross-machine DPAPI isolation test и portable behavior verification.

## Release gates

v0.4.0 не считается готовой, пока не выполнены одновременно:

1. production history не зависит от `localStorage` как authoritative backend;
2. privacy/retention реально применяются к persistence;
3. Windows persistent history защищена current-user DPAPI без plaintext fallback;
4. portable behavior соответствует задокументированной per-user policy;
5. migration/crash/readonly/manual QA выполнен на Windows;
6. #42 и #49 прошли свои release criteria;
7. финальный HEAD имеет зелёные Policy Pack, frontend/Playwright, Rust, Tauri/Windows/NSIS и security fuzz checks.
