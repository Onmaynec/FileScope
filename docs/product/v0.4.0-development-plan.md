# FileScope v0.4.0 — план разработки

## База

- рабочая ветка: `feature/v0.4.0`;
- точка ветвления: финальный hardening HEAD v0.3.4 `78ed2d6a5e4dfed31b348d22a8239d7ca45bf7a7`;
- `chore/v0.3.4-readiness` остаётся отдельной веткой для ручного QA и релизной подготовки;
- изменения v0.4.0 не переносятся обратно в v0.3.4 без отдельного решения.

## Главная цель

Перевести историю отчётов из WebView `localStorage` в контролируемое Rust/Tauri-хранилище, включить политику приватности и retention, определить системную защиту данных Windows и сохранить безопасную миграцию/rollback.

## Этап 1 — authoritative Rust/Tauri history storage

- реализовать versioned history envelope на стороне Rust;
- хранить данные в каталоге приложения, а не в WebView storage;
- ограничивать число отчётов и общий размер payload;
- валидировать storage/report schema до перезаписи;
- future/corrupted/oversized данные открывать безопасно без автоматического overwrite;
- использовать crash-safe запись через временный файл и атомарную публикацию поколения;
- сохранять предыдущую валидную генерацию для восстановления;
- добавить команды load/save/delete/replace/clear/inspect;
- добавить Rust regression tests на повреждение, future schema, размер и восстановление.

## Этап 2 — миграция localStorage → Rust storage

- Tauri storage всегда проверяется первым;
- WebView storage используется только как источник одноразовой миграции;
- перед persistence применять privacy minimization;
- после успешной миграции только Rust storage становится authoritative;
- legacy данные временно сохраняются для rollback, без двойной записи новых отчётов;
- migration failures не должны считать историю пустой и не должны уничтожать исходные данные.

## Этап 3 — privacy и retention

- переключатель сохранения истории;
- retention: текущая сессия / 1 / 7 / 30 дней / без автоудаления;
- полные пути по умолчанию не сохраняются;
- URL credentials удаляются всегда;
- query/fragment сохраняются только согласно политике пользователя;
- чувствительные headers не попадают в history persistence;
- UI показывает размер истории и фактический уровень защиты;
- полная очистка удаляет authoritative store и report payload migration backup.

## Этап 4 — Windows protection и portable mode

- исследовать и реализовать DPAPI для installed mode без собственной криптосхемы;
- ключи/секреты не хранятся в репозитории;
- определить поведение при недоступности DPAPI;
- отдельно описать portable mode, переносимость и границы защиты между Windows users;
- добавить диагностическое состояние защиты в UI.

## Этап 5 — hardening и release QA

- расширить property/fuzz invariants для нового storage contract;
- выполнить длительные scheduled fuzz runs для #49;
- frontend/Rust/Playwright/Windows regression suite;
- миграция реальной v0.3.x истории и rollback;
- аварийное завершение во время записи;
- readonly/недоступный app-data каталог;
- installer/portable/manual QA;
- обновить README, privacy/security docs, CHANGELOG и release notes.

## Release gates

v0.4.0 не считается готовой, пока production history зависит от `localStorage`, privacy/retention существуют только как helpers, DPAPI/portable policy не определены или #42/#49 не прошли требуемые проверки.
