# FileScope v0.3.1

FileScope v0.3.1 — исправляющий релиз для Windows, который снижает ложные PE-вердикты и унифицирует иконки приложения.

## Главное

- одиночные распространённые API больше не дают автоматический «Высокий риск»;
- подписанный установщик с одним `VirtualAlloc` должен получать информационный контекст, а не высокий вердикт;
- неподписанный FileScope с одним `ShellExecuteW` больше не оценивается как высокорисковый только по этим двум признакам;
- отсутствие Authenticode имеет низкий вес и не считается доказательством вредоносности;
- полные цепочки внедрения в процесс и сочетания загрузки с запуском сохраняют высокий уровень риска;
- shortcut, EXE, installer, окно, taskbar и tray используют единый фиолетовый логотип FileScope;
- все manifest-файлы синхронизированы с версией 0.3.1.

## Исправление оценки PE

В v0.3.0 любое совпадение со списком API повышенного внимания создавало индикатор высокой серьёзности. Это было слишком грубо: `VirtualAlloc` нужен множеству обычных программ, а `ShellExecuteW` применяется для открытия ссылок и файлов.

В v0.3.1 импорты оцениваются по комбинациям:

### Информационный контекст

- одиночный `VirtualAlloc`;
- одиночный `ShellExecuteA/W`;
- одиночный сетевой или hook API из списка повышенного внимания.

### Предупреждение

- две связанные части цепочки работы с памятью другого процесса без полного набора;
- дополнительные средние признаки, которые требуют проверки происхождения и подписи.

### Высокий риск

- `VirtualAllocEx` + `WriteProcessMemory` или `NtWriteVirtualMemory` + `CreateRemoteThread` или `NtCreateThreadEx`;
- `URLDownloadToFile` или `InternetOpenUrl` вместе с `WinExec` или `ShellExecute`;
- другие независимые сильные правила FileScope, не изменённые этим исправлением.

## Ожидаемые результаты повторной проверки

При отсутствии других признаков:

- FileScope-подобный PE без подписи и с одним `ShellExecuteW`: оценка 8/100, уровень «Угроз не обнаружено»;
- Telegram-подобный подписанный PE с одним `VirtualAlloc`: оценка 2/100, уровень «Угроз не обнаружено»;
- полная классическая цепочка внедрения: высокий уровень риска.

Эти сценарии закреплены Rust unit-тестами.

## Иконки Windows

Единый SVG-источник находится в `apps/desktop/src-tauri/icons/filescope-logo.svg`. Перед development- и production-сборкой команда Tauri генерирует стандартный Windows iconset, включая `icon.ico`. Bundle явно использует этот ICO.

После установки новой версии Windows может временно показывать старую иконку из системного кэша. Обычно помогает удалить старый ярлык, установить v0.3.1 и создать ярлык заново; при необходимости требуется обновление icon cache Windows.

## VirusTotal и Microsoft Defender

Portable EXE v0.3.0 получил единичное ML-срабатывание Microsoft при отсутствии срабатываний у большинства других движков. Это внешний вердикт поставщика и он не связан с ошибкой внутреннего Rule Engine FileScope.

v0.3.1 создаёт новый бинарный хеш, устраняет завышенную локальную оценку и сохраняет воспроизводимый release-процесс. Однако программный код не может гарантировать результат Microsoft Defender или VirusTotal.

Для устойчивого исправления репутации релиза необходимы:

- Authenticode или Microsoft Artifact Signing для installer и portable EXE;
- неизменность файла после подписи;
- отправка подтверждённого false positive через официальный Microsoft Security Intelligence submission portal;
- повторная проверка того же SHA-256 после обработки обращения.

Подробности: `docs/security/windows-reputation.md`.

## Проверка SHA-256

Скачайте оба бинарных файла и `SHA256SUMS.txt` из одного GitHub Release. В PowerShell выполните:

```powershell
Get-FileHash .\FileScope_0.3.1_x64-setup.exe -Algorithm SHA256
Get-FileHash .\FileScope_0.3.1_x64-portable.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

Не запускайте файлы при несовпадении контрольных сумм.

## Breaking changes

Breaking changes пользовательских отчётов и настроек отсутствуют.

## Известные ограничения

- наличие Authenticode-каталога пока определяется без проверки цепочки доверия и имени издателя;
- FileScope не использует VirusTotal API и не загружает пользовательские файлы во внешние сервисы;
- статический анализ не наблюдает поведение процесса;
- RAR и 7Z распознаются, но структурно пока не разбираются;
- внешний антивирусный false positive может сохраняться до решения соответствующего поставщика.
