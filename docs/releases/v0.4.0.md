# FileScope v0.4.0

> Release notes подготовлены заранее. Публикация v0.4.0 разрешена только после прохождения финального release preflight и всех ручных Windows QA gates.

## Главное

FileScope v0.4.0 переносит историю отчётов из WebView `localStorage` в authoritative Rust/Tauri storage в per-user app-data и добавляет системную защиту Windows DPAPI для новых history generations.

## История, приватность и recovery

- generation-based Rust/Tauri history store v2 с temp write, `sync_all` и atomic rename;
- восстановление предыдущей валидной generation при повреждении новой;
- ограничение размера history и количества reports;
- future/corrupted/oversized store остаётся read-only и не перезаписывается автоматически;
- миграция legacy v0.3.x history выполняется только после проверки нового store и не создаёт double-write;
- restart/retry и uncertain-commit сценарии миграции закреплены regression-тестами;
- privacy minimization для file paths, URL credentials/query/fragment и sensitive headers;
- retention: current session, 1/7/30 дней и без автоудаления;
- полная очистка Rust generations, session history и известных legacy payloads.

## Windows DPAPI

- новые Windows history generations защищаются `CryptProtectData` в scope текущего пользователя;
- чтение использует `CryptUnprotectData`;
- `CRYPTPROTECT_UI_FORBIDDEN` исключает системный prompt;
- machine-wide `CRYPTPROTECT_LOCAL_MACHINE` не используется;
- plaintext fallback при ошибке DPAPI отсутствует;
- encrypted generations используют wrapper `FSDPAPI1` и `.bin`;
- portable EXE не переносит persistent history: history остаётся в per-user app-data и привязана к Windows user через DPAPI.

## QA и hardening

- отдельные Rust fault regressions для interrupted publication, blocked/readonly storage и incomplete clear;
- migration/restart regression suite для retry и lost IPC response после commit;
- offline Windows history QA harness для DPAPI, restart snapshot, portable layout, full-clear и cross-user reject;
- property-based invariants для analyzer contracts;
- пять bounded cargo-fuzz targets: report deserialization, passive URL, Rule Engine, magic/PE и ZIP metadata/path handling;
- HTML export escaping закреплён synthetic regression payloads;
- fuzz workflow не использует malware samples, secrets, production environment или write permissions.

## Совместимость и обновление

При обновлении с v0.3.x legacy WebView history используется только как read-only migration source. После подтверждённой публикации в Rust/Tauri store он становится authoritative; новые reports в legacy history не записываются.

Рекомендуется не удалять пользовательские данные v0.3.x вручную до первого успешного запуска v0.4.0 и проверки migrated history.

## Известные release gates

Эти notes сами по себе не означают готовность релиза. Перед публикацией обязательны реальная Windows migration v0.3.x, process-kill recovery, ACL/locked-file QA, cross-user/cross-machine DPAPI isolation, portable/full-clear restart QA и подтверждённые extended fuzz runs. Финальный `pnpm release:preflight` работает fail-closed и требует структурированный release evidence для проверенного commit.
