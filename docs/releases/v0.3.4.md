# FileScope v0.3.4 — подготовка к v0.4.0

Статус: подготовлено к ручному тестированию владельцем. Релиз не опубликован.

## Основные изменения

- история переведена на асинхронный `ReportHistoryRepository`;
- legacy localStorage изолирован отдельным adapter;
- добавлен storage envelope v1, независимый от report schema v1;
- future, corrupted и oversized history не перезаписываются;
- future `reportSchemaVersion` защищён независимо от `storageVersion`, включая скрытый future report внутри текущего envelope;
- полное удаление истории удаляет current, legacy и migration-backup report payload и честно сообщает об ошибке WebView storage;
- подготовлены migration fixtures, rollback plan и manual QA checklist;
- добавлены privacy helpers для будущей минимизации путей, URL и headers;
- Rule Engine использует saturating accumulation и отделяет operational/resource limits от threat score;
- Rust backend повторно валидирует и ограничивает все `AnalysisLimits`, переданные через IPC;
- ZIP открывается через один контролируемый handle, отклоняет reparse/UNC policy cases и проверяет изменение файла;
- ZIP report больше не сериализует `NaN`/`Infinity`: бесконечный compression ratio имеет отдельное JSON-safe состояние;
- incomplete/stoppedByLimit отчёт больше не показывается в UI/HTML как полноценный зелёный verdict;
- очередь сообщает о дубликатах, выбирает существующий item и не сбрасывает ручной выбор отчёта при старте следующего задания;
- добавлены bounded cargo-fuzz targets для report JSON, passive URL и Rule Engine;
- добавлен read-only security fuzz workflow с коротким retention;
- CI получает readiness/release preflight и regression coverage для hardening-сценариев;
- GitHub Actions переведены на Node 24 runtime majors.

## Ручная проверка

Перед merge владелец выполняет `docs/product/v0.3.4-manual-qa.md`. PR остаётся Draft до подтверждения этого checklist и зелёного CI на финальном HEAD.

## Ограничение

Production-история v0.3.4 всё ещё физически хранится в WebView localStorage через совместимый legacy adapter. Переключение на Tauri storage, DPAPI, retention и пользовательские privacy settings выполняется в v0.4.0.

Связано с #63. Issues #42 и #49 получают подготовительный прогресс, но остаются открытыми до полной реализации v0.4.0.
