# FileScope v0.3.3 BugFix

FileScope v0.3.3 — исправление открытых задач с меткой `bug`, связанных с безопасностью активного URL-анализа, целостностью файловых отчётов, отменой заданий, версионированием отчётов и массовой очередью.

> Статус: версия находится в разработке и не опубликована. Перенос в `develop`, `main`, создание тега и релиза выполняются только после ручного тестирования владельцем.

## Закрываемые задачи после подтверждения тестирования

- #38 — SSRF, private IP и DNS rebinding в активном URL-анализе;
- #43 — единый источник версии и версия схемы отчёта;
- #44 — атомарный анализ файла, TOCTOU и reparse points;
- #45 — backend-cancellation и ресурсные бюджеты;
- #47 — единый канонический пассивный URL-анализ;
- #51 — drag-and-drop файлов и ZIP;
- #52 — понятная кнопка «Загрузить файлы»;
- #53 — доступный тематический Select/Listbox;
- #54 — master-detail очередь для 150+ объектов.

## Активная URL-проверка

- допускаются только HTTP и HTTPS;
- разрешены только стандартные порты 80 и 443;
- localhost, private, link-local, CGNAT, multicast, documentation, metadata и другие служебные диапазоны блокируются для IPv4 и IPv6;
- если DNS вернул хотя бы один запрещённый IP, запрос не выполняется;
- соединение закрепляется за проверенным IP для конкретного hop;
- автоматические redirect отключены;
- каждый redirect повторно проходит проверку схемы, порта, credentials, DNS и IP;
- downgrade с HTTPS на HTTP блокируется;
- URL со встроенным логином или паролем не отправляется в сеть;
- пароль удаляется из evidence, истории и экспорта;
- запрос не загружает страницу целиком: HEAD или Range `bytes=0-0`;
- отмена и timeout контролируются Rust backend.

## Атомарный анализ файлов

- путь проверяется через `symlink_metadata`;
- каталоги, symbolic links, junction и другие reparse points отклоняются;
- файл открывается один раз для чтения;
- SHA-256 и parser buffer формируются из одного потока байтов;
- PE не открывается повторно по исходному пути;
- до и после чтения сверяются сведения открытого file handle;
- при изменении размера или времени модификации отчёт не формируется;
- ошибка изменения файла имеет отдельный код `fileChanged`;
- чтение и parser memory ограничены отдельными бюджетами.

## Backend-cancellation

Каждое задание получает уникальный `jobId` и регистрируется в Rust `JobRegistry`.

- pending-задания отменяются до запуска;
- running-задание сначала получает статус «Останавливается»;
- статус «Отменено» появляется только после ответа Rust backend;
- file hashing и ZIP traversal проверяют cancel/deadline между порциями работы;
- DNS и HTTP ожидаются через cancel-aware `tokio::select!`;
- registry очищается после success, error, cancel и panic/join error;
- отменённое задание не сохраняется как завершённый отчёт.

## Версия и схема отчётов

Отчёт schema v1 содержит:

- `schemaVersion`;
- `appVersion`;
- `analyzerVersion`;
- `ruleSetVersion`;
- `createdBy`;
- `analysisCompleteness`.

Frontend получает версию из `apps/desktop/package.json` во время сборки. Rust использует `CARGO_PKG_VERSION`. Tauri, root package и contracts синхронизированы с `0.3.3`.

Старая история мигрируется в schema v1 с резервной копией исходного localStorage. Неизвестная будущая schema открывается только в read-only режиме без выдачи нового verdict.

JSON-экспорт содержит envelope с SHA-256 payload и явной пометкой, что экспорт не подписан цифровой подписью. HTML показывает версии schema/analyzer/rules и checksum.

## Очередь и интерфейс

- нативный drag-and-drop File Explorer;
- визуальные состояния idle, over, adding, success и rejected;
- каталоги, links/reparse points и non-ZIP в режиме архивов отклоняются до очереди;
- drop никогда не запускает анализ автоматически;
- основной текст кнопки: «Загрузить файлы»;
- системные `<select>` заменены доступным listbox;
- listbox поддерживает Enter, Space, Escape, ArrowUp/ArrowDown, Home/End и Tab;
- очередь и детали разделены на master-detail;
- список виртуализирован и не рендерит одновременно сотни строк;
- полный отчёт хранится отдельно от summary строки;
- доступны поиск, фильтры статуса/риска и предыдущий/следующий завершённый отчёт;
- очередь и отчёт имеют независимую прокрутку;
- на узком окне используются переключаемые панели «Очередь» и «Детали».

## Известные ограничения

- встроенный snapshot multi-label public suffix покрывает распространённые зоны, но не заменяет полный обновляемый Public Suffix List;
- наличие таблицы Authenticode не равно проверенной цепочке доверия;
- RAR и 7Z структурно не разбираются;
- статический анализ не наблюдает поведение процесса;
- sandbox, VirusTotal API и updater не входят в v0.3.3;
- внешний антивирусный false positive зависит от поставщика.
