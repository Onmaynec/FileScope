# FileScope v0.3.0

FileScope v0.3.0 исправляет lifecycle Windows-приложения и поведение официального EXE.

## Главное

- кнопка закрытия окна теперь надёжно обрабатывается нативным Rust/Tauri backend;
- режим «Сворачивать в трей» скрывает главное окно и оставляет FileScope работающим в системном трее;
- режим «Закрывать полностью» корректно завершает процесс;
- пункт «Выйти» в меню трея всегда полностью закрывает приложение;
- release EXE больше не открывает отдельное окно командной строки;
- закрытие консоли больше не может случайно завершить официальную release-сборку;
- добавлены Rust unit-тесты lifecycle-состояния;
- версии frontend, contracts, Tauri и Rust синхронизированы с 0.3.0.

## Причина изменений

В v0.2.0 обработчик кнопки закрытия находился на JavaScript-стороне. При недоступности нативного listener или ошибке его регистрации окно могло не скрываться и не закрываться ожидаемым образом. В v0.3.0 решение перенесено в Rust backend и работает независимо от состояния React-интерфейса.

Отдельная консоль появлялась из-за сборки desktop entry point как console subsystem. В release-режиме теперь используется Windows GUI subsystem. Debug-сборки по-прежнему могут показывать консоль для диагностики.

## Поведение кнопки закрытия

### Сворачивать в трей

Это значение используется по умолчанию. Нажатие на крестик:

1. отменяет уничтожение главного окна;
2. скрывает окно;
3. сохраняет процесс и системный трей;
4. позволяет восстановить окно через пункт «Открыть FileScope».

### Закрывать полностью

Нажатие на крестик завершает весь процесс FileScope. Настройка находится в разделе «Настройки → При закрытии окна».

## Проверка

Релиз проходит:

- ESLint;
- TypeScript strict;
- frontend unit-тесты;
- production frontend build;
- Playwright smoke-тесты;
- `cargo fmt --all --check`;
- Rust unit-тесты;
- `cargo check`;
- Tauri production build;
- Windows x64 и NSIS packaging;
- проверку структуры Policy Pack Veilbyte.

Проверенная CI-сборка перед публикацией содержала:

- `filescope.exe` — PE32+ x64, `IMAGE_SUBSYSTEM_WINDOWS_GUI`;
- `FileScope_0.3.0_x64-setup.exe` — Windows GUI subsystem;
- artifact digest GitHub Actions: `sha256:c2e99d2e6283dcfd5cec4aed3a2af1ee52c60d5eabd90be97e0891f6d46f43f1`.

Эта статическая проверка подтверждает отсутствие console subsystem в release EXE. Фактическое поведение трея дополнительно обеспечивается Rust unit-тестами и нативным обработчиком `CloseRequested`.

## Поддерживаемая платформа

- Windows 10 x64;
- Windows 11 x64;
- установщик NSIS для текущего пользователя;
- portable x64 EXE.

Другие ОС и ARM64 в v0.3.0 официально не поддерживаются.

## Проверка SHA-256

Скачайте бинарные файлы и `SHA256SUMS.txt` из одного GitHub Release. В PowerShell выполните:

```powershell
Get-FileHash .\FileScope_0.3.0_x64-setup.exe -Algorithm SHA256
Get-FileHash .\FileScope_0.3.0_x64-portable.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

Полученные значения должны полностью совпасть со строками в `SHA256SUMS.txt`. Не запускайте файл при несовпадении контрольной суммы.

## Безопасность и приватность

Обновление не добавляет внешних API, телеметрию или новые сетевые разрешения. Исследуемые файлы не запускаются и не отправляются во внешние сервисы.

## Breaking changes

Breaking changes пользовательских форматов и отчётов отсутствуют.

## Известные ограничения

- RAR и 7Z распознаются, но структурно пока не разбираются;
- Authenticode определяется по наличию каталога сертификатов без проверки цепочки доверия;
- активный URL-анализ не исполняет JavaScript и не загружает страницу целиком;
- Hyper-V Sandbox и поведенческий анализ не входят в v0.3.0.
